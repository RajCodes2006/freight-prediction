01 · EXECUTIVE SUMMARY

02 · PROBLEM STATEMENT

Chartering needs more than a market number

The problem is not only forecasting freight rates. A useful procurement decision also needs to know whether the vessel physically fits, what the complete voyage costs, how much congestion risk is present, and whether a contract can improve the expected outcome versus continued spot-market exposure.

01ForecastingIdentify entry windows and forward market direction instead of relying only on today's spot observation.
02ConstraintsRespect berth limits, vessel dimensions, cargo requirements and congestion at both ends of the voyage.
03EconomicsCompare voyage cost, spot exposure, contract pricing and risk-adjusted savings in one view.
03 · SOLUTION & UVP

One integrated decision engine, not three disconnected tools

Freight Prediction carries the same cargo scenario through every stage of the decision. The system first establishes a market outlook, then checks physical feasibility, prices the feasible options, evaluates contract economics and finally returns a confidence-aware recommendation.

  • Feasibility before price. A vessel that cannot physically serve the route is filtered out before voyage cost becomes a decision factor.
  • Graded forecasts. Each horizon gets its own confidence assessment so short and long horizons are not treated as equally reliable by default.
  • Visible economics. Freight, vessel time, bunker and port charges can be compared across feasible vessel classes.
  • Contract math. Duration, discount assumptions and risk scenarios are combined into expected savings.
  • Transparency. The response distinguishes validated output from prototype assumptions instead of hiding uncertainty behind a single confident number.

06 · DATA & FORECASTING

Validated models with explicit prototype boundaries

The current forecasting layer uses historical Baltic dry-bulk data covering August 2012 to July 2019. Four vessel-class indices are forecast over four horizons, giving sixteen forecast targets in total.

  • Candidate algorithms include XGBoost, LightGBM and Random Forest, benchmarked against a persistence baseline.
  • Validation uses chronological splits and walk-forward evaluation rather than random shuffling.
  • The model registry records the serving method per vessel class and horizon; where boosted models did not reliably beat persistence, the simpler baseline is used.
  • An optional live-market calibration layer can adjust the current index level when benchmark data is available, while keeping the trained model responsible for forecast shape.
Prototype data transparency: route-specific freight USD/MT, bunker costs, port charges, sailing time and some queue inputs may still be assumptions in the prototype. The interface is designed to label those values rather than present them as live commercial quotations.
